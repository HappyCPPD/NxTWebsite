#Step 2 - Recognise the puzzle

The nine 400×400 tiles are slices of one 1200×1200 QR code smashed into a 3×3 grid and shuffled. Two giveaways:

  • Module size ≈ 24.49 px (measured from the smallest dark/white run), so a 1200 px image is ≈ 49 modules → a QR version 6..8 with a quiet zone.
  • Three tiles (007, 008, 009) each contain a full QR finder pattern (the 1:1:3:1:1 bullseye). The other six are dense data modules. One tile (006) carries the small alignment pattern.

Locating the finder centre in each of those tiles by template-matching the ideal 7-module finder (module = 1200/49):

#Step 3 - Solve the geometry (this is the whole trick)

Work out where a valid QR's finders should be. Assume a QR version 6 = 41 modules, module m = 24.49 px, drawn with a quiet zone q:

  • top-left finder centre = (q + 3.5m, q + 3.5m)
  • top-right finder centre = (q + 37.5m, q + 3.5m)
  • bottom-left finder centre = (q + 3.5m, q + 37.5m)

From tile 008's (183,183): q + 3.5·24.49 = 183 → q ≈ 97 px. Then q + 37.5·24.49 = 97 + 918 ≈ 1015.

  • Tile 008 local (183,183) → top-left cell (row 0, col 0) ✓
  • Tile 009 local (216,183): 216 + 800 = 1016 → top-right cell (row 0, col 2) ✓
  • Tile 007 local (183,216): 216 + 800 = 1016 → bottom-left cell (row 2, col 0) ✓

No rotation needed - the corner tiles drop straight in. Only the 6 data tiles remain: {001, 002, 003, 004, 005, 006} into the 6 open cells {1,3,4,5,7,8} → just 6! = 720 candidate assemblies instead of 9! = 362 880.
