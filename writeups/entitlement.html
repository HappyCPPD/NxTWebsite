Flag: hiCTF{>o<_C0ngrats_Her3_1s_Y0ur_HI4_Subscript1on_^_^}

Verified: the string the binary emits is the 64-byte buffer the program itself builds, and its byte-sum equals the program's own acceptance constant 0x133d (sum = 4925 = 0x133d).

#Binary structure

Entitlement is a 15048-byte ELF64 with no section headers. It is a self-loader: the entry stub (0x40abd8) decrypts a live image into 0x400000–0x408000 (via a memfd), sets PR_SET_DUMPABLE=0 and reads /proc/self/status:TracerPid as anti-debug. The cleared live image was recovered to work/live.bin; every real function lives in 0x401000–0x405000.

#Stage 1 - Serial (bit-serial VM)

main @ 0x401110 reads %63s, requires length 16, hex-decodes it to 64-bit r8, then runs a private bytecode VM.

  • 0x404330 first decrypts the VM program in place at 0x407080 (0x18c bytes). The key stream is a KDF (0x4042c0) seeded by a 64-bit hash of the VM handler code bytes 0x404560–0x404702. Anti-debug (0x403830) XOR-corrupts that seed if a tracer is present - this is why "the key doesn't work" under gdb: the bytecode is never correctly decrypted. It also sets the guard byte at 0x40721c, which makes repeat calls skip re-decryption.

  • VM (0x404560): dispatch table @ 0x405060, 8 registers, 4-byte instructions [opcode, dst, src1, src2], opcodes 0 - 16 (LOAD_CONST/LOAD_INPUT/COPY/XOR/NOT/ROL/ROR/SHL/SHR/ ADD/SUB/BRANCH_NZ/JMP/LOOKUP/RET), constant table @ 0x405240.

#Stage 2 - Activation code (anomalous-curve ECDLP)

The 25 hex characters are read as a 100-bit integer k, then the program performs a double-and-add scalar multiplication of a base point by k on an elliptic curve over F_M, M = 0x8c817b4a4c0f170cd5aab18cf (prime, 100 bits). String Serial > etc. live at 0x4050xx; the group operation is 0x403ad0 which uses the modular inverse routine 0x403900 (exponent M-2, i.e. Fermat). The base point constants are @ 0x405670 / 0x405680.

#Flag derivation (with the intentional work factor)

After both checks pass, the flag buffer is table64[i] XOR buf2[i] where table64 is the 64-byte constant @ 0x405200 and buf2 is a SHA-256-based expansion of the activation data. Before that, 0x4037b0 runs a deliberate 0xc350 × 0x2710 = 500,000,000-iteration big-integer square/reduce loop (a proof-of-work / anti-reversing delay). The loop genuinely feeds the digest, so it must actually run; it is why the program "hangs" for ~15 - 20 min before printing. The final check is that the byte-sum of the produced 64-byte buffer equals 0x133d, and on success it prints Correct! The flag is %s\n.

#Verification

  • Stage-1 serial: (serial^C11)^13 ^ C13 == 0x30cefbec2e4bc466 ✔
  • Stage-2: k*P == Q on E/F_M ✔ (Smart's attack)
  • End-to-end: ./Entitlement prints the flag, and its byte-sum equals the program's own 0x133d gate ✔
