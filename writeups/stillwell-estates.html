#The bug - absolute-path override

/opt/stillwell/server.js (read via the same primitive):

It only rejects the literal .. substring, but path.resolve(base, name) discards base when name is absolute. So document: "/etc/passwd" reads any file on the box. (Encoded ..%2f, ....//, backslashes and plain ../ are rejected; absolute paths are not.)

#Exploitation

  • document: "/etc/passwd" → arbitrary absolute file read confirmed

  • document: "/proc/self/cmdline" → node server.js (cwd /opt/stillwell)

  • document: "/proc/self/environ" → leak of the exec-time environment:

Startup (initializePrivateRecords) writes the flag into $SECRET_DIR/escrow-ledger.txt and then deletes RCTF_FLAG from process.env but /proc/self/environ still holds the exec-time environment, so the token is readable directly. Reading the ledger by its own path returns a masked form (hiCTF{...a}); routing through /proc/self/root returns the unmasked token, matching the env value exactly:

#Root cause / fix

path.resolve() base-substitution: the resolver never verifies the resolved path stays inside PARTNER_DOCS. Fix: reject absolute paths and check abs.startsWith(PARTNER_DOCS + path.sep) after resolve (the static-file handler already does this correctly).
