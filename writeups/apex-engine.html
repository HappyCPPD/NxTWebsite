#Protections

Full RELRO + PIE + canary means no GOT/ret2win path: this is a pure logic/race bug.

#Analysis (Ghidra decompile → main @0x12c0, and two thread workers)

Globals (0x43e0+):

  • 0x43e0 balance (u64, starts 100) · 0x43e8 escrow (u64) · 0x43f0 VIP flag (u32) · 0x43f4 "root" word (u32, never written)

Menu: 1 view, 2 escrow transfer, 3 withdraw, 4 upgrade VIP (10 000), 5 vault enclave, 6 exit.

#Bug 1 - TOCTOU double-spend (FUN_00101ef0 settlement worker)

menu 2 only checks balance < amount at submit time, then spawns a detached thread:

Because the deduction happens 25 ms after the balance check, submitting two orders of the full balance (100) back-to-back makes both threads pass the check, then both deduct: 100 - 100 - 100 = 0xFFFFFFFFFFFFFF9C (unsigned underflow → huge balance). The "funds cannot be double-spent" risk model is exactly what is broken.

#Bug 2 - TOCTOU file-filter bypass (FUN_00101d80 enclave stream worker)

Vault is gated behind VIP (0x43f0). Once inside, create slot (stride 0xb0, path at +0x24), stream slot spawns a worker that does:

The path buffer is shared with menu 3 = Edit Document Target Path, which we can call while the worker sleeps. So: stream with the benign default target ("Document_Preview", contains no "flag" → filter passes), then during the 25 ms sleep rewrite the slot path to ./flag.txt (or /flag). The worker wakes and opens the new path → the flag filter is bypassed and the flag is printed.

Note: /flag opens, and on failure path=="/flag" falls back to ./flag.txt; both contain "flag", so only the race makes them reachable. The 0x43f4 "root" bypass word is dead code - only the race works.
