#The challenge

We are given chall.py and output.json. A black box evaluated a secret polynomial

over GF(p) with p a 61-bit prime, T = 24 sparse terms, distinct exponents e_i in [1, p-2], nonzero coefficients. We only got 48 samples:

where g is a generator of GF(p)*. The flag is AES-GCM encrypted under sha256(";".join(f"{e}:{c}")) over the true term list (sorted by exponent), with the ciphertext/tag/nonce published.

The challenge text explicitly rules out the two obvious dead ends: interpolating a degree-p-2 polynomial needs p-1 points (we have 48), and guessing which 24 of the p-1 exponents are live is C(p-1,24) ~ 10^421.

#The key insight: it is a sum of exponentials → a linear recurrence

Substitute a_i = g^(e_i) mod p. Then

This is a sum of T exponentials in j (Prony's problem, 1795). Any such sequence satisfies a linear recurrence of order T whose characteristic polynomial is

i.e. sum_{k=0}^{T} u_k * log[j+k] = 0 with u_T = 1.

We have exactly 2T = 48 samples, which is the minimum needed (Berlekamp - Massey / Prony). Setting up the T x T Hankel system for j = 0..T-1:

One Gaussian elimination mod p gives C.

#Recovering the exponents: root finding + Pohlig - Hellman

The roots of C over GF(p) are exactly the a_i = g^{e_i} (they are all in the base field, so gcd(C, X^p - X) = C). We split C into linear factors with Cantor - Zassenhaus (random r, gcd(C, (X+r)^((p-1)/2) - 1)), isolating each a_i. Degree is only 24, so this is instant.

Then, since a_i = g^{e_i}, each exponent is a discrete log base g. The challenge deliberately built p-1 from small primes so this is easy:

Pohlig - Hellman reduces each discrete log to a subgroup of order < 2^22, solved by baby-step giant-step (~2048 steps each), then CRT. All 24 exponents recovered.

#Recovering the coefficients

With the a_i known, log[j] = sum_i c_i a_i^j is again a linear system - a 24×24 Vandermonde matrix V[j][i] = a_i^j - solved mod p.

Important pitfall: the mapping a_i -> e_i = dlog(a_i) is not order preserving, so you must solve the Vandermonde for coefficients in the same order the roots came out, then attach each coefficient to its own exponent via dlog, and only then sort by exponent. Sorting the root values and the exponents independently (a natural-looking shortcut) silently mismatches the pairs and fails the AES-GCM tag check.

Verification: the recovered term list reproduces all 48 published evaluations exactly (verify recurrence: True).
