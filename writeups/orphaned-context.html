#TL;DR - the flag

Recovered from the relay's sealed record /incidents/IR-7731/seal via the orphaned-context bug (below). Reproduced on 6 independently provisioned instances; every read returns the same 51 bytes (sha256 b749ad4b82d2d71cadbac6be614d0f324bdb311a581178fdbe079a290a027791).

#Recon: the operator API is hidden from a normal wordlist

The read-only console (/, /app.js) only calls GET /api/relay/status, /api/relay/events, /api/incidents. Its own comment says the privileged actions ("open captures, store notes, run recovery previews") are "operator-API actions, documented in the handout".

The handout is not attached on the platform for this challenge (challenge object files: [], and - unlike every other challenge in the event - the description carries no object-storage link). It had to be recovered by observation.

Discovery detail that matters: the action routes are POST-only, so a GET-based wordlist reports them as non-existent. Fuzzing two path segments (ffuf -mc all -w w1.txt:W1 -w w2.txt:W2 -u $B/api/W1/W2 -fr not_found) surfaces them immediately, because a real POST-only route answers GET -> 405 while an unknown route answers 404 {"error":"not_found"}.

Complete operator API:

Method Path Body Effect
POST /api/capture/open {} (body ignored) allocates a slot; returns request_id, slot, epoch, recovery_descriptor
POST /api/capture/commit {"request_id":...} retires the descriptor, frees the slot
POST /api/capture/interrupt {"request_id":...} retains the descriptor, frees the slot
POST /api/note/store {"text":...} stores a note in a free slot (bumps epoch)
POST /api/note/discard {"note_id":...,"epoch":...} frees a stored note
POST /api/recover/preview {"recovery_descriptor":...} evaluates the slot's current occupant

Read-only: GET /api/relay/status, /api/relay/events, /api/incidents, /api/health.

Descriptor format: base64url(payload) + "." + sig(32 bytes); payload = {"rid","slot","epoch","kind":"recovery"}. Signature is instance-bound; all tamper attempts → 400 invalid_descriptor. The bug is not forging a descriptor - it is reusing a legitimately issued one.

#The bug

recover/preview validates the descriptor, extracts its slot, then resolves the live occupant of that slot and evaluates it, without comparing the occupant's epoch to the descriptor's epoch. It records the mismatch and proceeds:

A capture occupant evaluates as format:"inert" (preview ""); a note occupant evaluates as format:"relay-maint/1" with trusted:true - so an attacker note is executed by the relay's diagnostic interpreter.

#Exhaustive negatives (map is really closed, no second flag)

  • help → fixed verb list help, whoami, pwd, ls [path], cat <path>. Unknown verbs (reveal transcript seal open recover evidence audit exec env printenv source run use set) → unknown verb: X. No hidden verb.
  • Path probes all no such path: /flag /seal /relay/{flag,seal,config,secrets,key,.flag,.env} /incidents/IR-7731/{flag,notes,seal.txt,seal.flag,.seal} /incidents/IR-7604/seal /handout /relay/handout.
  • Traversal collapsed/rejected: ../, %2e%2e, ..%2f, //flag, /./././flag, null-byte tricks, ./→"is a directory".
  • API surface re-fuzzed (GET+POST, root and /api/*, 38 KB wordlist): every non-index hit is 404 not_found; only the six operator routes exist. Malformed bodies, wrong methods, huge descriptors → no 5xx, no stack trace, no leak.
  • Static assets (/, /app.js, /style.css) and all GET JSON contain no hiCTF{.
  • A matched recovery (open → preview, no orphan) returns format:"inert", preview:""; after commit the descriptor is 410 descriptor_retired. So the orphan-note path is the only one that yields interpreter output.
