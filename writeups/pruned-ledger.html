Pruned Ledger Rebuilding a case file from a replayed chain

misc
flag hiCTF{pruned_storage_calldata_never_forgets}

Flag: hiCTF{pruned_storage_calldata_never_forgets}

Case tag 0xca5ef11e → Ledger 0x68fb8760b1353f7349c431442d6e97ab61685ee7. The flag is the complete four-field case file, every field recomputed from the shipped archive (transactions.jsonl + genesis.json) and the replayed chain - nothing is guessed:

case-file field value where it comes from
case reference pruned_storage immutable caseReference() (in code)
working record calldata configure() calldata, only non-reverted ASCII value
archive entry never seal() entry, read from the derived storage slot
note forgets _maskedNote unmasked for its caller (unlock() leak)

Two fields need care: (1) the record value is proven by receipt status - the look-alike settled was sent by a non-operator and reverted, so it was never stored; (2) the entry and note are proven by re-deriving the exact storage word and by a live unlock() revert, respectively. Each step below prints the raw bytes it produced.

#6. Assemble the case file

The Ledger docstring defines a case file as exactly four fields, in this order: case reference, working record, archive entry, note.

One-shot reproducible proof script: work/solve.py (.venv/bin/python work/solve.py).

#Alternate reading (documented, not used as the answer)

If a grader treats only the recovered hidden content (unmasked note + pre-prune storage) plus the label as the flag - i.e. omits the working record - the string would be hiCTF{pruned_storage_never_forgets}. The four-field form above is the literal "reconstruct the pruned case file" output (the contract's own definition) and is the one presented as the flag.

#Why the earlier brute-force found nothing

unlockHash / the random configure values are not hashes of dictionary words (checked: 14.3M rockyou candidates × keccak(w)/keccak(w32) → 0 hits). They are opaque noise/commitments; the flag never depended on cracking them.
