GhostBus UART nonce and a word-swapped AES record

misc
flag hiCTF{gh0st_bu5_uart_n0nc3_r3v3al_9c3f12}

Category: Hardware / firmware crypto · ghost_bus.zip (sha256 8ffeac83…)

#Artifact

  • capture.csv / capture.vcd - UART bus probe between the hub MCU and the secure element
  • flash_dump.bin (1 MiB) - external SPI NOR (holds a recovery copy of the firmware + a sealed record)
  • firmware.elf - MCU firmware
  • diagram.png, below

#Method

  1. UART decode. Frames are AA 55 <len> <cmd> <payload> CRC16/Modbus. The MCU's "hidden read" request is len=0, cmd=0x10; the secure element's reply is len=0x10, cmd=0x10 carrying a fixed 16-byte nonce (it returns the same nonce every read - not a fresh random):

  2. Key derivation (firmware, capstone): key = SHA256(salt24 || nonce)[:16], with salt24 from rodata 0x08000ca0 (04325a9c117f3da0c0ffee5aa55a00ff1234567890abcdef):

  3. Open the sealed region. External flash holds the sealed v2 record (48 B) at offset 0x6A000 (the v1 record at 0x68000 is "rotated out" decoy). Main reads it, byte-swaps each 4-byte word, then AES-128-CBC-decrypts with IV = nonce, strips PKCS#7 and validates hiCTF{…}.

#Verification

The decryption ends in 7 bytes of clean PKCS#7 padding (0x07 × 7) and a well-formed hiCTF{…} token - the padding is the structural that the key/IV/word-swap are correct (IV = nonce confirmed by the fact that only the first CBC block was garbage otherwise).
