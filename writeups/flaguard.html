FlaGuard shadow dex decoy and a missing flip()

rev
flag isfcr{sh4d0w_cl455l04d3r_tr1ckery}

#0. Prompt

A small Android app called FlaGuard turned up on a forum, pitched as the strictest flag-format validator around. Nobody will say which flag it actually accepts. Flag format: isfcr{...}.

The wording ("which flag it actually accepts") is the whole clue: there are two candidate flags, and only true runtime behaviour picks the winner. The answer turns out to hinge on a one-line buffer bug.

#1. Triage

Unzipping shows a deliberately tiny app:

Two odd assets stand out: theme.pack (high entropy - looks encrypted) and palette.webp (a "lossless WebP" that the code nonetheless consults). strings classes.dex surfaces isfcr{, sha256, SecretKeySpec/javax.crypto, and the classes App, Analytics, FlagChecker, MainActivity, obf/Veil.

#2. First candidate - the visible checker

FlagChecker.java in classes.dex:

A deterministic affine recurrence: every term except b[k] is known, so each byte inverts directly - b[k] = (C[k] - P[k%6] - i*131) & 0xFFFF, then i = C[k].

34 bytes, validates.

The app intends to boot a second dex in memory. This is where the decoy lives.

#4. App.bind() - the intended (but broken) shadow

attachBaseContext() runs bind() before anything else:

Notes:

  • palette.webp is not a palette: it is a 128-byte key-shard container. The shard offset is (palette[16] & 63) + 64 = 82.
  • Analytics.enabled() is true only when the package name ends in .internal; the shipped package dev.srspace.flaguard does not, so the trust.chain branch (asset index 12) is skipped and the IV is the plain sha256(classes.dex_hash || bArr[0:16])[:16].
  • theme.pack is AES-256-CBC/NoPadding; length 1296 is a clean multiple of 16 and the plaintext is a dex\n038 file of declared size 1288.

In principle the last lines would shadow the visible checker: replacing the app ClassLoader's parent with the in-memory dex loader means parent-first lookup finds the hidden FlagChecker before the app's own dex. But the buffer is never prepared for reading.

#5. The bug that decides the challenge

After put, the buffer's position == limit == capacity, i.e. remaining() == 0. A ByteBuffer is read from position to limit, and InMemoryDexClassLoader expects the dex bytes starting at position. There is no bb.flip() (or bb.rewind()/bb.position(0)) before the buffer is handed to the constructor. The loader therefore sees an empty slice and contributes no classes at all.

Consequence at runtime:

  1. bind() still succeeds (no exception - an empty in-memory dex file yields an empty loader rather than a hard failure).
  2. The app ClassLoader's parent points at the inert loader.
  3. MainActivity.verify() calls dev.srspace.flaguard.FlagChecker.check(). Parent-first lookup asks the inert loader (miss), then resolves from the app's own classes.dex - the visible FlagChecker.
  4. The visible checker is what actually validates input.

So the shadowed/decrypted flag is the decoy, and the ordinary static checker is the real one. The name of the hidden flag (p4r3nt_f1rst_d3x_1s_s0_m34n) narrates the trick the author wanted you to fall for; the accepted flag (sh4d0w_cl455l04d3r_tr1ckery) calls the dynamic loader itself the trickery.

#6. The decoy dex (for completeness)

Reproducing the derivation (see solve.py):

openssl enc -aes-256-cbc -d -nopad -K <key> -iv <iv> -in theme.pack yields a valid dex\n038 (1288 bytes) containing a single class with the same FQN as the visible one:

Inverting that recurrence (b[k] = (T[k]^M[k]^i)&255; i = (i^b[k])&255, i0 = 90) gives the decoy isfcr{p4r3nt_f1rst_d3x_1s_s0_m34n}. Because the loader never receives the bytes (section 5), this class is never registered and this flag is never accepted.

#7. Which flag does the app actually accept?

# Location Flag Role
1 visible classes.dex isfcr{sh4d0w_cl455l04d3r_tr1ckery} accepted
2 shadow dex (theme.pack) isfcr{p4r3nt_f1rst_d3x_1s_s0_m34n} decoy

Decided by the missing ByteBuffer.flip() in App.bind(), which leaves the in-memory dex loader empty so the intended parent-first shadowing never occurs.
