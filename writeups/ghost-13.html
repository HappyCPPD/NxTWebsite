GHOST-13 journal rollover, ECDSA nonce reuse, DTMF

forensics
flag isfcr{ghost13_dc8f84a256fa64108b6c75a151a1474d}

#Overview

The GHOST-13 line controller survived a brief power failure and, on restart, its maintenance gateway received "two diagnostic writes that should never have looked alike." We are given a full plant snapshot and must reconstruct the active configuration + reboot sequence, then recover the diagnostic secret sealed in the maintenance update.

The solve is a chain where every artifact feeds the next:

The hint "two diagnostic writes that should never have looked alike" is the giveaway for the core vulnerability: ECDSA nonce reuse.

#Stage 1 - Active configuration (plc_program.bin, G13L)

The IEC program image is a header + 8 × 128-byte G13P config slots + 8 × 64-byte G13J commit journals.

Per the field-service excerpt, a slot holds sequence:u16, epoch:u16 @4, ID[16] @8, salt[16] @24, keypad_trim[8] @84, CRC32(bytes 0..119) @120, and a commit word @124: CRC ^ 0x13c0ffee ^ (sequence<<16 | epoch).

A journal binds journal_sequence, slot_index, slot_sequence, epoch, slot_CRC @4..15, with CRC32(bytes 0..55) @56 and commit @60: CRC ^ 0xa91f0eed ^ (jseq<<16 | jseq).

Finding the active slot:

  • A slot is activated only if it has a valid matching journal (CRC + commit valid on both, and the journal's bound fields equal the slot's).
  • Journals 6 (bad CRC) and 7 (bad commit) are invalid → slots 6 & 7 not activated.
  • The sequences wrap (65533, 65534, 65535, 0, 1, 2, 3, 4), so 16-bit serial-number arithmetic gives the ordering. The highest valid activated journal is jseq = 2.

→ Active slot = index 5:

The reboot sequence in uart_log.txt corroborates this: watchdog exception 0x06 → CPU brownout → journal frontier restored after 16-bit rollover.

#Stage 2 - Firmware constants (plc_firmware.bin, G13W)

64-byte header + a directory of 24-byte section entries (tag[4], offset, length, crc32, aux, flags, ). Valid sections:

  • VMBC - signing VM program (unused for the flag path)
  • KDFD - G13K + a 32-byte factory constant, then label strings
  • PUBK - P256 + big-endian Qx, Qy
  • RECV - retired v1 recovery key (unused)

#Stage 3 - Recover the signing scalar (plc_traffic.pcap)

Reassembly path: TCP reassemble → Modbus/TCP FC16 (write multiple registers) → G13C fragments → padded G13F frame.

Each G13C fragment: magic[4], stream_id:u16, index:u8, data_count:u8, frame_len:u16, parity:u8, reserved:u8, payload[40], CRC16/CCITT-FALSE:u16. Register address = 0x4200 + 20*index (data) or 0x4300 (parity index 3).

  • Validated every fragment by CRC16 and expected register address (drops the damaged fragment and retransmissions).
  • Data slices 0..2 are 40-byte pieces; index 3 is their bytewise XOR parity. Streams 0x41 and 0x42 were each missing one slice → restored via XOR parity.
  • Three G13F frames recovered (streams 0x41, 0x42, 0x43).

#Key takeaways

  • Serial-number arithmetic is needed to pick the newest wrapped sequence, not raw >.
  • ECDSA nonce reuse (same r) across two signatures leaks the private scalar instantly.
  • Erasure coding (XOR parity) lets you rebuild a dropped fragment.
  • Every hash/CRC in the chain is a checkpoint - validating them early catches the damaged fragment, the un-activated slots, and a wrong target image before they waste your time.
