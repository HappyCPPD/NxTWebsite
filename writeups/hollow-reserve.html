Hollow Reserve Flash loan against a spot-price oracle

#Goal

Drain the on-chain reserve vault below 10% of its initial balance (Setup.isSolved()).

#Deployed addresses (instance https://hollow-reserve-15d83fd51591.chall.hiddeninvestigations.net, chain id 31337)

#Contract interfaces recovered from bytecode (no source published; IPFS metadata 404s)

  • Vault.reserveBalance() = RES.balanceOf(vault) = 1e25. Vault.lend(address,uint256) (facility only) → RES.transfer.
  • Facility.borrow(uint256 collateralAmount, uint256 borrowAmount):
    1. COL.transferFrom(msg.sender, facility, collateralAmount) (reverts "facility: no collateral" if 0)
    2. price = priceFeed.getPrice() (= Pool.spotPrice())
    3. require(borrowAmount <= price * collateralAmount / 1e18 * 7500/10000) ("facility: over LTV")
    4. collateralOf[msg.sender] += collateralAmount; debtOf[msg.sender] += borrowAmount
    5. Vault.lend(msg.sender, borrowAmount) LTV = 7500 bps = 75%. The LTV check only uses the collateral passed in THAT call and ignores existing debt - but that alone is not enough to drain (a fair AMM + 75% LTV just decays each leverage cycle).
  • Facility.repay(uint256) - proportional collateral release, needs real RES.
  • Pool = Uniswap-V2-style constant-product AMM COL/RES, reserves 1e21 COL / 1e23 RES, 0.3% fee. spotPrice() = reserveRes * 1e18 / reserveCol = 1e20 (i.e. 100 RES per COL). Custom swap wrappers: 40f788d2(uint256 amountResIn, uint256 minColOut) buys COL (RES in → COL out); dce0772c(uint256 amountColIn, uint256 minResOut) sells COL.
  • priceFeed.getPrice() simply forwards to Pool.spotPrice() (source recorded via the pool's own storage slot 0). No deviation guard, no TWAP - a raw, flash-manipulable spot price.
  • Flash lender is ERC-3156: flashLoan(receiver, token, amount, bytes), maxFlashLoan(RES) = 5e24, flashFee = 0 (free). It holds 5e24 RES.
  • Market (1e25 RES / 1e23 COL, maxDeviationBps = 500) is the safe that is NOT wired to the facility - it is the decoy.

#Root cause

The facility values collateral with the pool's instantaneous spot price. A thin pool plus a free 5e24-RES flash loan lets an attacker skew the price arbitrarily inside one transaction, deposit collateral bought at the skewed price, and borrow far more than it is worth.

#Exploit (src/Exploit.sol, one transaction)

  1. FlashLender.flashLoan(this, RES, 5e24, "") - free.
  2. Inside onFlashLoan: dump the whole 5e24 RES into the pool with Pool.40f788d2(resBal, 0), receiving ~9.8e20 COL. Pool reserves become ~5.1e24 RES / ~2.0e19 COL → spotPrice ≈ 2.5e23 (>1000x).
  3. Deposit that COL and borrow: Facility.borrow(colBal, vault.reserveBalance() - 5e22); the LTV test (0.75 · 2.5e23 · 9.8e20 / 1e18 ≈ 2e26) passes easily, so the vault empties down to 5e22.
  4. Return the ERC-3156 magic value; the lender pulls amount + fee back with transferFrom (approve it in advance - do NOT self-transfer the repayment, that double-pays and reverts "ERC20: balance").
  5. Sweep remaining RES/COL to the player.

Result: vault 1e25 → 5e22, Setup.isSolved() == true, flag served by GET /flag.

Deployed exploit: 0x2cfc3303eaCB6fb02aAb40BD6A423b5EA7c429ad (tx 0x7827f3a7f7d2aad40f7cb96ee18e1dc5fe2ad094f934c5d5fa26bcf0b2e032ec).

#Notes / pitfalls

  • cast send <to> 0x<4byte-selector> <args> treats the hex as the FULL calldata and silently drops the extra args - build the full calldata string instead.
  • Two near-identical AMMs exist (Pool and Market); confirm which one the feed actually reads (priceFeed.source()) instead of assuming.
  • Local anvil --fork-url <instance> (with -a 0; the instancer 502s on the default dev accounts) gives a free, resettable sandbox - but the fork dies when the live instance expires.
