#0. Prerequisite (recap of the foothold)

  • Recon: 22 (OpenSSH 9.2p1) and 80 (nginx → "Anadyne Systems · Alert Review Console").
  • Default creds: the /login page prints analyst / analyst; the footer hints that "keystroke telemetry via libechotap.so" is enabled.
  • SSTI → RCE: /api/alert/preview renders the body through Jinja2: {{7*7}} → 49; escalate with {{ self.__init__.__globals__.__builtins__.__import__("os").popen("id").read() }} → RCE as analyst (uid=1001, groups analyst, echo-log).
  • Sentinel primitive: reading /opt/sentinel/sentinel.py (via the SSTI RCE) shows a Unix socket /run/sentinel/ctrl.sock whose exec_shell handler is gated by a time-based nonce sha256("{minute_epoch}:{SALT}")[:16] with SALT = "sentinel-salt-v1-a3b7c2d9", accepting ±1 minute of drift. The sentinel runs with CAP_DAC_READ_SEARCH - it can read any file regardless of permissions.

Full script and detail: ../echochamber-user/writeup.md.

#1. The escalation - inherited CAP_DAC_READ_SEARCH

The sentinel process holds CAP_DAC_READ_SEARCH. Any child process it spawns inherits that capability, and exec_shell lets us spawn an arbitrary command as the sentinel user. So we can read /root/root.txt directly through the sentinel socket - no classic privesc required.

#3. Takeaway

"To win the game, play a different game": instead of fighting file permissions, abuse the capability (CAP_DAC_READ_SEARCH) that a reachable service already holds and passes to its children. The sentinel socket was the intended root path all along.
