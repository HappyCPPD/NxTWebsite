Rocinate LCG orbit and exponent relations

crypto

Flag: hiCTF{lmaoooo_w0t???y0u_d1d_17_??435p37++}

#1. Challenge

extracted/chall.py (also extracted/chall.txt = print(a, b, N, Zs, Cs, Ts)):

We are given a, b, N, Zs, Cs, Ts (space-separated; parse.py → data.json). zs[i] = r[i]·s^{Cs[i]}, Ts[i] = r[i]^e, and r[i] is the LCG orbit of the secret r0. r0, e, s are unknown.

Plan: recover r0 from the Mersenne-Twister stream used by random, then r[i] = LCG^i(r0), so A_i := Zs[i]/r[i] = s^{Cs[i]} (mod N); since the published Cs[i] are the exponents and gcd(Cs)=1, a single extended-Euclid combination gives s exactly.

#2. Mersenne-Twister recovery (the hard part)

Zs[i] ~4090 bits, N is 2047-bit, so a,b,Cs[i] are 2047-bit random.randint(1,N) values. Three traps:

  1. randint(1,N) is not a bare getrandbits(2047). It is 1 + _randbelow(N), i.e. g = getrandbits(2047); while g >= N: g = getrandbits(2047). With 2^2047/N ≈ 1.28 the rejection probability is ≈ 0.219, so consecutive published draws are not contiguous in the MT word stream (whole 64-word rejected attempts are missing).
  2. getrandbits(2047) = 64 genrand words, LSB-first, and the 64th word is >>1 - its low bit is lost. So each draw exposes 64 words but the LSB of every word[63] is unobservable from the value.
  3. The twist is not injective: CPython's in-place twist never uses state[0], so a 32-bit word is lost per inverse step - naive "untemper + inverse-twist all the way back" drifts. This is why earlier attempts failed.

Working method (solver.py):

  • Find a contiguous run. Build the per-draw 64-word decomposition of D = [a, b] + Cs; a run D[j..j+L-1] is contiguous iff untempering its first 624 words and twisting reproduces the following words. The data yields runs of length 11 at j = 20, 22 and of length 10 at j = 17..26.
  • Fix the lost LSBs. Untemper the window (624 words) with the lost bits set to 0; the true state differs only by U1 = untemper(1) at the 9 truncated word positions (temper/untemper are GF(2)-linear). Brute-force the 2^9 choices, and keep the combo whose forward-generated MT stream reproduces all subsequent published Cs (rejection-aware). Exactly one combo passes (for the winning run: j=17, combo=471).
  • Walk backwards to the start. For the anchor at absolute position A = 64·T (T = number of attempts before the anchor), untwist K = ceil(A/624) times; if the residual "free-word" corruption lands at negative positions the state is exact on >=0. Enumerate T and the two leading draws; r0 is the first accepted block (value < N), e the second. Decisive check: pow(r0, e, N) == Ts[0].

Run: .venv/bin/python solver.py data.json

#3. The exponent trick

With r0 known, Rs follow from the published LCG. Then for every i:

Run the iterative extended Euclidean algorithm over the published exponents Cs[0..99] to get Bezout coefficients with Σ k_i·Cs[i] = g = gcd(Cs). Here g = 1, so

s is a ~27-byte integer → long_to_bytes(s) = b'hiCTF{...}'.

#4. Proof (re-encryption) - final.py

That is: the reconstructed stream reproduces every published Cs value; the recovered r0,e re-encrypt to all 100 published Ts; and the recovered s re-encrypts all 100 published Zs exactly (Zs[i] = r[i]·pow(s,Cs[i],N), no final reduction).
