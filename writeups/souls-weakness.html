Soul's Weakness gets() overflow to a win function

pwn 200 pts
flag OWASP{S0ul_St0ne_Buff3r_0v3rfl0w}

Verified live against the remote service on 2026-10-09 (see exploit.py REMOTE).

#1. Triage

Not stripped, No PIE → fixed addresses, and the symbol table hands us the goal directly:

Two smoking guns at once: an unstripped soul_stone function and a call to gets(). The story writes itself.

#2. Static analysis

main just sets the stdio buffers to unbuffered and calls vault:

vault prints the vault banner, reads a line with gets into a 0x20-byte stack buffer, echoes it back, and returns:

gets has no length limit, so the 32-byte buffer trivially overruns the saved RBP and the saved return address. No canary, so there is nothing to leak or preserve.

soul_stone is the target. It prints the unlock message and the flag:

(The flag string is additionally visible with strings soul - the remote served the exact same string, confirming the binary and the deployed service match.)

#3. Offset calculation

Standard x86-64 prologue: push rbp; mov rbp,rsp; sub rsp,0x20. The buffer starts at rbp-0x20.

So: b'A' * 40 + p64(0x4011b6).

Alignment note: soul_stone begins with endbr64; push rbp; mov rbp,rsp and calls puts, so if the libc puts implementation ever needed 16-byte stack alignment at the call site we might need a leading ret gadget. It does not matter here - puts was fine and the exploit worked first try both local and remote.

#4. Exploit

exploit.py:

Run: python3 exploit.py REMOTE (or python3 exploit.py for the local run).

Remote output:

The AAAAAAAA... echo is the 32 buffer bytes plus the two A bytes that clobbered the low byte of saved RBP; the ret then jumps straight into soul_stone (0x4011b6 written shows up as the \x11\x40 in the echoed line).

#5. Root cause

Return-address overwrite via gets() into a fixed 32-byte stack buffer, with no and no PIE - a textbook ret2win.

#6. Remediation

  • Never use gets(); use fgets(buf, sizeof buf, stdin) or getline.
  • Compile with -fstack-protector-all (canary) and -fPIE -pie ( on the code segment) to raise the bar; keep NX/RELRO as-is or go Full RELRO.
  • Keep the flag out of the client binary - read it from a server-side file/env so a leaked/strings'd binary cannot hand it over.
