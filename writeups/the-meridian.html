The Meridian prototype pollution to derived key

web
flag isfcr{d33p_m3rg3_p0llut3s_th3_pr0v3n4nc3_v4ult_1n_th3_m3r1d14n}

A static client-side "museum" app. The vault is a sealed AES-256-GCM blob; the only way in is a prototype-polluted shared-view link. Two decoy flags line the way: the legacy console token and a "wrong pepper" self-test string.

#Files

  • solve.py - offline solve (unmask → registrar audit → key derivation → decrypt)
  • exploit-payload.txt - the browser payload / URL
  • src/ - mirror of the deployed site (JS + data snapshot)
  • results.txt - captured solve output

#1. Recon

GET https://isfcrpesu-the-meridian.chals.io/ is a hash-router SPA. Scripts:

file role
vendor/mcrypto.js self-contained SHA-256 + AES-256-GCM
assets/js/core.js config engine, provenance check, vault client
data/meridian-data.js 14 exhibits, vault blob, legacy masked lines
assets/js/legacy/provenance-v2.js registrar signing helper (decoy pepper)
assets/js/app.js router, settings, share-link, /staff, /vault views

Two footers links, #/staff and #/vault, are the targets.

#2. The two peppers (the first trap)

core.js holds PEPPER = "meridian::provenance::v3::do-not-share". provenance-v2.js claims it is "the pepper the registrar desk signs with" and ships a self-test. Running that self-test with its own v2 pepper yields:

i.e. v2 is the wrong pepper. Unmasking the legacy console lines confirms it: the v3 pepper decodes cleanly, v2 produces garbage.

#4. Registrar audit → descriptor

core.js registrarVerify = sha256(accession|title|curator|<pepper>)[:12]. hasCertificate only checks sig.length === 12, so the green badge is worthless exactly as the journal says ("signatures are facts, the badge is not").

Re-signing each exhibit with the v3 pepper and comparing to its stored sig:

accession curator verifies
MRD-1971-0148 E. Vantar ✓
MRD-1984-0912 R. Oikawa ✓

MRD-2003-0777 K. Adeyemi ✓
MRD-2011-0410 S. Marchetti ✓

(8 exhibits carry a sig but fail the audit - stale certificates from the key rotation described in the journal. MRD-1962-0007 and MRD-2022-0140 have no sig.)

#6. Getting the descriptor past the app (the real vuln)

openVault needs cfg.vault, but sanitizeConfig deletes any own vault key and strips non-allowlisted feature flags - so the console (features.vault === true) and a naive descriptor both die. The intended path is prototype pollution through a shared view link, whose only guard is:

The regex runs on the raw decoded text; JSON.parse still expands \u escapes in keys. So:

parseStatePayload passes (no literal match) → JSON.parse makes an own __proto__ data property → deepMerge's target[k] = ... fires the __proto__ setter and writes vault onto Object.prototype → sanitizeConfig sees it as inherited (so does not delete it) → openVault reads cfg.vault off the prototype chain and the dial spins open.

#7. Dead ends / decoys

  • isfcr{l3g4cy_st4ff_c0ns0l3_1s_n0t_th3_v4ult} - console token, explicitly not the vault.
  • isfcr{wr0ng_p3pp3r_r1ght_curs3} - v2 self-test, the wrong pepper.
  • Verdigris provenance hex → vfspe{ce0i3a4ap3_cy4dh3_j4f_n_s0et3el} - a scrambled non-flag ("exactly as trustworthy as the certificate beside it").
