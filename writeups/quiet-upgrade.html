#Win condition

Setup.isSolved() - the treasury's STL reserve must fall below 1% of its starting 5_000_000 ether. The only way STL leaves Treasury is release(to, amount), gated on msg.sender == settlementSystem, and settlementSystem is wired to the proxy.

#The bug: naive proxy slot collision

SettlementProxy keeps its pointers in plain sequential slots:

but SettlementV1 - reached only through the proxy's delegatecall fallback - declares its own storage starting at slot 0:

registerBranch(operator) is open (there is no registrar wired in) and writes branchOperator = operator, i.e. proxy slot 0 → proxy.admin. That is a direct admin takeover. Slot 1 is never written by V1, so the implementation pointer is not clobbered by accident.

#Exploit chain

  1. proxy.registerBranch(player) - fallback → delegatecall into V1 → proxy.admin = player. (Confirmed via cast call proxy 'admin()(address)' before proceeding.)
  2. Deploy a malicious implementation and prove it was built for this proxy: proxiableSlot() must return keccak256(abi.encodePacked(keccak256("quiet-upgrade.proxiable"), address(this))) with address(this) = the proxy. Reproduced off-chain: 0xbd66a804753105e7deead67d70049a37cd9a22a3f7e9631e4bcb7f4b89c25adf.
  3. proxy.upgradeTo(malicious) - admin-only, guard satisfied.
  4. proxy.drain() - delegatecall into the malicious impl; it calls treasury.release(player, reserveBalance()). Because the code runs in the proxy's context, the external call to Treasury originates from the proxy address, so require(msg.sender == settlementSystem) passes.
