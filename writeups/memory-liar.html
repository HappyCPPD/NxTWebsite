#Analysis

The image is 16 MB of mostly zero padding; a 64 KB-block non-zero scan localises the only live region at 0x300000 - 0x35FFFF (mirrored into region3.bin). No Volatility profile support was needed - this is a synthetic image.

  1. Region map - all data lives at 0x200000..0x35FFFF; the rest is zeros.
  2. Decoy confirmed - the "clean audit" log block is bait and self-describes as fake:The "process list" only holds textbook built-ins: System, smss.exe, csrss.exe, wininit.exe, services.exe, lsass.exe, svchost.exe, svchost.exe, explorer.exe, notepad.exe.
  3. Hidden process (DKOM) - grepping all *.exe names in the raw image surfaces one name that is not in the enumerated list:A DKOM rootkit unlinks the process's EPROCESS from ActiveProcessLinks, so every tool that walks PsActiveProcessHead (including the "clean" audit) misses it even though the process is still resident - hence "cross-check the process list" against an independent source (pool scan / raw byte scan). Technique marker + C2 in the image:
  4. Recover the flag - a record at 0x35F000: tag ROOT9, then flags 05, XOR key 5D, length 0x33, then 51 bytes of single-byte-XOR ciphertext. Key is stored in the clear; validated on the hiCTF{ prefix (0x35^0x5D='h', 0x34^0x5D='i', 0x1e^0x5D='C'...).
