KuMir Behind the Wall - Writeup

#Challenge

Category: Web

The Robot hit a wall, the homework wasn't saved, and the admin is fixing the printer. After the school server migration, the reference answer for the final assignment robot-final went missing. Explore the Kletochka forum and recover it before the teacher schedules a retake.

Target: https://kumir-behind-the-wall.solarctf.ru

#Architecture

From docker-compose.yml:

  • web - Flask/gunicorn on port 8000, on networks govnonet (internal) and edge (public)
  • kumir-checker - on govnonet only, health at http://127.0.0.1:8081/health

The govnonet network is internal: true, so kumir-checker is unreachable from the internet but reachable from the web service. Classic SSRF setup.

#Recon - Forum Breadcrumbs

#1. The target: checker API

In /topic/final-work, post #2 by admin_7b reveals:

The checker is on the internal network. The assignment we need is robot-final.

#2. The SSRF vector: avatar URL

In /topic/avatar and /profile, the forum lets users set an avatar by URL:

The avatar is then proxied through /api/avatar/me:

The server fetches the user-supplied URL server-side and proxies the response body through /api/avatar/me. This is a Server-Side Request Forgery (SSRF) vector.

#3. Teacher hint about error reports

In /topic/final-work, post #3, the teacher says:

На неверный ответ проверяльщик пишет подробно - специально для преподавателя.

("The checker writes detailed reports for wrong answers - specifically for the teacher.")

This hints that submitting a wrong answer yields useful information.

#Vulnerability Class

SSRF (Server-Side Request Forgery) - The avatar URL feature allows users to specify arbitrary URLs, which the server fetches without restricting the target to external hosts. This allows access to internal services on the govnonet network that are otherwise unreachable from the internet.
