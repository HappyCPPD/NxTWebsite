#3. skin.dat is a hidden DEX (LCG-xor)

App.onCreate (jadx --show-bad-code) builds an asset name from {69,78,94,89,68,4,88,64,66,69,5,79,74,95} ^ 43 = neuro/skin.dat, then decrypts it:

Decrypting gives a 5,340-byte DEX (lab.dex, sha256 f70eeb6f155f2cd9d026017e7d14166c9437636a6865197a764a987af1a2cdff) holding three hidden classes: Trig, LabActivity, LabHold.

#4. The hidden "lab" and the flag path

AboutActivity.onCreate attaches a click listener to brand_word. The handler builds a class name with XOR-61 ({94,82,80,19,...} → com.solarlabs.neuropet.lab.Trig) and calls Trig.hit(); on success it starts a second XOR-61-decoded class (...lab.LabActivity) from the in-memory loader; otherwise it toasts lab_unavailable.

Trig.hit() = 5 taps within 1500 ms (TAPS=5, WINDOW_MS=1500).

LabActivity's LabView.onDraw steps a phase counter; once, at phase 2:

So the flag path is: run the native script devroom, then read query index 0. (The screen only ever draws "4/4" - the flag is never displayed, so you must instrument or emulate; that's why the challenge needs RE rather than just running the app.)

#5. Driving the native core directly (no JNI, no watchdog)

libneurocore.so exports four JNI functions that are thin bridges. Disassembling the x86_64 slice shows the real entry points, and they are plain C:

nInit additionally spawns a detached anti-analysis thread (scans /proc/self/maps for frida, gum-js, gadget, substrate, /data/local/tmp/re.frida.server and _exit(7)s on a hit). Calling init/run/query directly bypasses both the JNI plumbing and that thread.

Running the Android x86_64 .so under glibc needs two fixes:

  1. It demands a bionic symbol version LIBC. Patch a copy: rewrite the DT_VERNEED, DT_VERNEEDNUM, DT_VERSYM tags in .dynamic to DT_DEBUG (21) - the loader then ignores versioning. (patch_so.py)
  2. It needs bionic's __errno. Supply it via LD_PRELOAD (bionic_shim.so: int *__errno(void){return __errno_location();}). A dummy liblog.so and libc.so symlink complete the stub dir.

#6. The four "neurons" and their encodings

Four query indices return one fragment each, each prefixed with a marker and each encoded differently - the marker is what identifies the inverse transform:
