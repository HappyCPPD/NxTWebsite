the-aggregate-remembers federated gradient inversion

AI
flag isfcr{9b1aa6a53205a859c14cc5e4}

#TL;DR

A federated linear-regression client leaked its per-round weight updates. Each round's update is delta = -lr * (weighted_mean_gradient + weight_decay * weights). We invert that to recover the mean gradient of each client at each training checkpoint, show the target client's per-checkpoint gradient lies on a rank-2 affine map (so its batch is exactly two records), project into the resulting 2-D subspace, and solve a small nonlinear least-squares for the two 16-byte raw records.

#Data model

data.json:

  • model.dimension = 16 - each raw record is 16 bytes.
  • Feature map: x[j] = (raw[permutation[j]] - center[j]) / scale[j] for j = 0..15, then a constant bias x[16] = 1. So the weight vector is 17-D (dimension + 1).
  • Every example has label 1.
  • lr = 1/8, weight_decay = 1/64.
  • 3 clients: ['5bd9ed5b49', '6806bb153e', '41940163bb']; target = 6806bb153e (index 1).
  • 6 checkpoints (each a 17-D weight vector) and 61 round updates. 60 are cohort = "acquisition-A"; one is acquisition-B (decoy / not used).
  • Each update carries checkpoint (the pre-round weights w), mix (per-client mixing weights, integers 1..3), and the observed 17-D delta.

Loss is the mean half-squared error. With label 1, the per-example gradient is (w·x - 1) x. For a client c with batch B_c (fixed across rounds) define the mean gradient

#Step 1 - recover each client's gradient at each checkpoint (identifiability)

Component i of g_r depends only on row i of each S_c and t_c[i]:

Because all rounds share only 6 distinct checkpoints, the per-component observation matrix is sum_c beta_{r,c} e_c ⊗ [w_r, -1], whose rank is exactly 3 clients x 6 checkpoints = 18. Confirmed numerically: a global least-squares on the naive (A_c, b_c) unknowns has rank 306 = 18 x 17 (heavily underdetermined), but per component it is rank 18. So the only thing identifiable is

We solve a 60-equation least-squares per component for the 18 unknowns {h_c(w_k)[i]} (coefficient beta_{r,c} on the matching checkpoint). Residual < 0.011, rank 18 exactly. Using normalized beta = mix/M; the unnormalized variant gives rank-5 differences and huge residuals, confirming mix is normalized.

#Step 2 - batch size and the 2-D record subspace

For a client, h_c(w_{k}) - h_c(w_{0}) = S_c (w_k - w_0). Since (for a 2-record batch) S_c = ½(x1x1ᵀ + x2x2ᵀ), every such difference is a combination of x1 and x2, so the matrix of differences has rank ≤ 2:

Two large singular values then noise ⇒ each client's batch is exactly two records, and the record space U = span{x1, x2} is the 2-D column space of the differences.

#Step 3 - solve for the two records

h_c(w) = ½( x1(x1·w) + x2(x2·w) − x1 − x2 ) for the 6 checkpoints, with the constraint x1[16] = x2[16] = 1 (bias feature). Non-linear least squares over x (initialized by projecting into U) converges instantly. Raw bytes raw[perm[j]] = x[j]*scale[j] + center[j] land within 0.2 of integers:

#Notes / pitfalls

  • The acquisition-B round is decoy - restricted to acquisition-A as stated.
  • mix must be normalized by its sum; unnormalized breaks the rank-2 signature.
  • The whole attack hinges on the checkpoint reuse: with only 6 distinct weight vectors, per-component identifiability is capped at 18, which is exactly enough to pin down S_c w - t_c at those 6 points, and the rank-2 structure of a 2-record batch turns 6 points into an exactly solvable system.
