The-Loom second-order reversible automaton

rev
flag isfcr{2nd_0rd3r_r3v_c3ll_aut0m8}

#1. Triage

.text is only 0x341 bytes - small enough to read by hand. Everything lives in one function at 0x4003c0 (called from _start), plus a tiny helper at 0x4006c0.

Imports of interest: fread, memcmp, fprintf, puts. No crypto library, no syscalls - pure integer/bit arithmetic. Good sign: hand-rolled logic is invertible by inspection.

#2. What the checker does

#2.1 Read + expand (0x4003c0 .. 0x40044e)

So the state is a 256-bit array, laid out LSB-first: bit i of the state is bit i%8 of input byte i/8.

#2.2 The loom: ~1e6 iterations (0x400450 .. 0x4004ec)

Two things matter here:

  • The update is nonlinear (& and | on bits), so it is not a GF(2)-linear sponge you can solve with linear algebra.

  • The three buffers rotate as a 3-cycle. Tracking the contents, the middle buffer evolves as

    i.e. an order-2 (second-order) nonlinear recurrence - a "second-order cellular automaton". The name of the flag was the tell.

#2.3 The verdict (0x40051e .. 0x4005c4)

After the loop, 1,000,002 rotations have happened and 1000002 ≡ 0 (mod 3), so the buffer roles are back to (A,B,C); the final outer iteration therefore wrote its result into the C slot and left P[1000002] sitting in the B slot.

#3. The trick: second order ⇒ run it backward

Forward, 1e6 iterations of a nonlinear CA is a wall. But the recurrence is order two, and that is its own inverse:

Given the two consecutive published states (P[1000002], P[1000003]) we can walk backward one step at a time, all the way to P[0], which is the bit-expansion of the input. 1,000,002 cheap O(256) steps instead of guessing 256 bits.

#4. Verification

The recovered bytes are fed straight back into the original binary - the only that counts:

Confirmed: isfcr{2nd_0rd3r_r3v_c3ll_aut0m8} (matches the event's isfcr{...} format, cf. free-lunch, hidden-weights, implicit-twins). The flag string is coherent English - "2nd order rev cell autom8" - so it is the intended answer, not a coincidental preimage.

#5. Takeaways

  • The instruction "hand it 32 bytes, it says nope" plus a tiny binary points at a checkable predicate, not a game - the fastest path is to invert the predicate, not search the input space.
  • A nonlinear, high-iteration map is not automatically hard: state the update order. Order-1 nonlinear maps may be hard to invert; order-2 maps falling out of a shift-register/xor-with-previous-state construction are reversible given two consecutive states. The challenge name (The Loom) and the flag (2nd order) both signpost exactly this.
  • Always re-drive the original checker with the candidate - self-consistent algebra plus the real binary is airtight evidence.
