File Viewer ZIP symlink to arbitrary file read

#Recon

"File Viewer" is a Zip Checker: upload a ZIP, and the app lists the extracted members, each served back through a generated URL of the form

Uploading a benign archive and opening /<token>/hello.txt returns the member's contents - the app extracts the archive and serves the members back.

#The bug - ZIP symlink → arbitrary file read

A ZIP entry can be a symbolic link rather than a regular file. When the server extracts the archive and follows the link while serving the member, an attacker can read files outside the extraction directory. Path-traversal (../), command injection and template injection all failed; the symlink entry succeeded.

#Flag

#Root cause / fix

Extraction into a per-upload directory is not enough if the file-serving endpoint follows symlinks out of it. Reject symlink entries in untrusted archives, or resolve each served path and verify it stays inside the upload root.
