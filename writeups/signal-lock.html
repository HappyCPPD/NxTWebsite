#Artifact

A stripped, compiled BEAM module signal_lock with a single entry point verify/1. Per the brief it validates a client's session-integrity token; a correct token returns {ok, <<"hiCTF{...}">>}.

#Method

abstract_code is absent, so disassemble the BEAM and read the SSA:

verify/1 does, in order:

  1. is_binary(Token) and byte_size(Token) == 8 (exactly 8 bytes);
  2. bs_match an unsigned 64-bit big-endian integer out of the token;
  3. transform(Int) == 12675316763487955908 (0xAFE7C5708F40EBC4);
  4. on match, unlock(Int) returns {ok, <<Flag/binary>>}.

#Verification

The strongest possible : the challenge's own unmodified module returns the flag for the candidate token - the token is accepted by signal_lock:verify/1, not merely "plausible". No brute force was used; the token was derived from the arithmetic in transform/1.

#Tooling notes

  • This is a compiled .beam (no debug info); use beam_disasm:file/1, not beam_lib:chunks(...,[abstract_code]).
  • The module is gzip-compressed BEAM (gzip compressed data, original size 1624).
